# Historical CEF 156.0.14 source build

This note records why an earlier revision of the fork considered building CEF/Chromium
itself. It is no longer an instruction. The repository now pins a prebuilt
**CEF 156.0.30 / Chromium 156.0.8078.96** through `scripts/fetch-cef.sh`.

## Why the source build existed

CEF 156.0.14 had native-handle SharedImages support
([CEF #4238](https://github.com/chromiumembedded/cef/pull/4238)), but Chromium could
hand a DMA-BUF to the consumer before the GPU producer had finished writing it
([CEF #4313](https://github.com/chromiumembedded/cef/issues/4313)). Tearing and
partially rendered frames were possible. `glFinish()` in obs-browser only completes
the consumer copy; it does not create the missing cross-process producer dependency.

The proposed producer-side patch ([CEF #4314](https://github.com/chromiumembedded/cef/pull/4314))
was therefore kept as a local patch and applied to a self-built CEF distribution.

## What replaced it

The fix was backported to M156 as CEF commit `57389f04a61a` and is included in
prebuilt distributions starting with **156.0.28**. PR #4314 itself was closed without
being merged; the separate backport commit is the relevant change. The local patch
and the long Chromium build instructions have been removed from the repository.

Pinning 156.0.30 is not a validation of this fork on NVIDIA. Re-run the target
fixture, lifecycle and streaming checks after changing the CEF pin.
